# 当前记忆与上下文压缩

本页描述实现现状，区分聊天原始记录、模型生成的摘要和跨会话记忆。摘要不是执行回执；记忆不授予权限，也不能自动重放工具操作。

## 存储位置

统一位于用户数据目录：Windows 默认 `%LOCALAPPDATA%/Xuloom`；macOS 默认 `~/Library/Application Support/Xuloom`；Linux 默认 `$XDG_DATA_HOME/xuloom`，未设置时为 `~/.local/share/xuloom`。显式设置 `XULOOM_DATA_DIR` 可覆盖。

- 原始会话与执行回执保存在中央 history 下，不写入工作目录的 `.xuloom`。
- 会话摘要：`memory/sessions/<session_id>/summary.md`。记录当前任务、用户约束、来源、产物、已做／未做事项、错误和真实工具／worker 状态。
- 跨会话记忆：`memory/projects/<目录哈希>/*.md` 和索引 `MEMORY.md`。按工作目录隔离，并非全局共享的所有会话记忆。不同独立会话使用不同目录时，默认也不会共享这一组记忆。

## 何时更新和读取

会话摘要在估算上下文达到 10,000 tokens 后启用；之后需同时满足约 5,000 tokens 的增长和三次工具调用，再安排后台更新。默认每节最多 8,000 字符，总计最多 48,000 字符；压缩时按摘要模型预算携带摘录，至多 4,096 tokens，并保留完整 notes 路径。

长期记忆在正常回合结束时检查，默认累积三个回合后才具备提取资格；已有提取任务时不重复启动。候选内容是偏好、目录约定、可复用的错误修复和工作方法。提取说明要求排除凭据、外部材料里的指令、未核实的助手说法，以及用户要求遗忘的内容。这些仍是模型生成的信息，不保证事实与语义永远正确。

后续请求会刷新并加载当前目录记忆，默认每文件最多 6,000 字符、总计 12,000 字符，省略会有标记。不是每次发送全部聊天历史或全部记忆文件。子代理不负责写入主会话的长期记忆；后台任务有明确拥有者，关闭、取消和切换连接时进行取消／清理。已有更新游标和原子保存，保存失败不会推进成功游标。

这两类摘要／提取使用当前引擎的压缩器连接，会调用模型并消耗额度；可以使用配置的摘要模型，否则沿用当前模型。会话摘要单次最多预留 8,192 输出 tokens，长期记忆最多 4,096；请求还受该模型剩余窗口和既有目标／委派预算约束。输入无法容纳时保留已有记忆与未确认游标，拒绝超窗请求。当前不是纯规则记忆库，也没有向量检索或独立的完整记忆管理设置页。

## 上下文压缩

1. 按连接、模型读取窗口配置；可在模型连接的「更多设置 → 上下文与压缩」填写。窗口包含输入和输出。未声明时使用 `XULOOM_CONTEXT_WINDOW`，否则保守按 65,536 tokens；不按模型名猜第三方网关的真实能力。输出默认预留窗口的八分之一，至多 16,384；近期原文默认保留至多 20,000 tokens，并按小窗口收缩。
2. 计量包含系统指令、记忆、工具定义、对话和输出预留。取消固定消息条数触发及固定 52k／44k 二次阈值。优先本地 tokenizer，缺失时采用保守的多语言估算；图片另计预算。供应商实际输入回执只校准相同路由、指令与历史前缀，历史改变后不沿用旧校准。估算仍不是供应商精确计费。
3. 改变历史前，归档完整原始消息及原生压缩状态到 `context-*.json`。长工具结果即使在近期范围内也可单独归档，返回带路径的头尾预览；完整内容可以通过既有文件读取工具取回。
4. 以 token 而非消息数选择近期范围，工具调用与对应结果必须完整配对。旧摘要参与下一次摘要；多批摘要按摘要模型窗口推进，携带上一批摘要。单个不可分割输入过大、空摘要、压缩反而增大或最终仍超预算时明确失败，不伪装为压缩成功。
5. 确定性保留原始／最新用户请求的内容或可核对引用、目标身份、约束和真实执行状态。摘要不产生授权。完成后重新计算完整请求；只有更小且处于预算内、原子检查点保存成功，才报告完成。
6. 保存失败或取消时恢复原内存消息与边界，保留归档；压缩期间到达的新输入不会被旧摘要覆盖。人类消息中的伪压缩标记不能隐藏先前历史。已有单写者和保存版本校验继续适用，没有第二套会话存储。

## 查看与手动压缩

App：输入框「＋ → 上下文」，查看估算、组成、上次压缩前后用量和耗时、摘要／记忆额外请求的输入输出用量。可以填写重点并压缩，也可以停止压缩。窗口参数放在模型高级设置里，基本 API 表单保持简洁。查看状态不会调用模型。

自动压缩时，对话过程会显示小图标与「正在压缩上下文…」；只有新上下文保存成功后才显示「上下文已自动压缩」。失败、取消和中断分别显示对应状态。提示沿用本轮执行记录保存，过程折叠或重新打开会话后仍可见；未达到压缩条件时不显示。

交互 CLI：`/context`；`/compact 保留重点`。

正式 CLI（状态查询不占写锁，也不会启动 MCP）：

```sh
xuloom context status --session SESSION_ID --cwd /workspace --json
xuloom context compact --session SESSION_ID --cwd /workspace --focus "保留来源和未完成事项" --json
```

## 可选的 OpenAI 原生压缩

只有明确将此模型压缩方式选为「OpenAI Responses」才启用；服务须同时实现 Responses 和 `/responses/compact`。普通 OpenAI 兼容 Chat 接口仍默认使用通用文本摘要，不会尝试不支持的端点。

返回的完整 canonical output（包括 opaque/encrypted compaction 和 reasoning）原样存储和续传，不转换为 Chat 消息。后续自定义工具仍走原有授权与执行入口，不接受未声明的供应商托管工具。切换模型／连接时退出原生状态，保留本地原始历史供通用路径重新压缩；不会将旧模型的加密状态转发给另一个模型。

`/compact` 原生端点没有可强制执行的输出 token 上限，因此有限目标／委派输出预算下明确拒绝原生压缩，需选择通用摘要。其他供应商的专属压缩协议没有被冒充为已实现。

压缩需要模型请求，不能保证绝不漏掉语义细节。工具／子代理真实状态仍从结构化记录核对，缺证据时读取原归档。外部 Codex、Claude Code、Pi、DSH 后端的内部上下文由对应外部程序管理，Xuloom 不私自运行原生压缩来改写它们。
