# 上下文压缩改进验收

日期：2026-11-03。本轮复用既有会话、单写者、原子保存、产物归档和模型预算，没有新建独立的摘要数据库、任务调度器或模型服务。

实现范围见[记忆与上下文压缩](memory-and-compaction.md)：按模型窗口及请求完整组成计量、保留近期 token 和完整工具配对、分批合并历史摘要、带明确路径的工具输出归档、确定性目标与用户请求引用、压缩后验证和保存失败回滚。现有 session notes 也按预算携带，并保留完整来源。

App 的「＋ → 上下文」和交互／正式 CLI 提供查看、手动压缩及保留重点。App 可以停止正在等待的压缩请求；取消保留原记录。高级窗口配置不占基本 API 表单。状态查询不请求模型，正式 CLI 的只读状态查询不拿写锁、不启动 MCP。

显式启用的 OpenAI Responses 走真实 SDK 的 `/responses` 和 `/responses/compact`；canonical output／opaque compaction／encrypted reasoning 原样保存、恢复和续传。不将其转为 Chat 历史，不接受未声明的供应商托管工具。刷新同一路由保留状态，切换模型、地址、凭据或退出原生模式后清理路由特定状态。原生端点不支持可执行的输出上限，有限目标／委派输出预算下明确拒绝原生压缩，使用通用摘要。

本地证据：

- 新压缩故障／契约测试 23 项通过，包括失败回滚、分批摘要、窗口过大／不可分割输入、空或反增摘要、新输入竞态、取消 owned 请求、伪边界文本、回执校准、工具配对、图片 base64 不按文字计量、混合图片／长文本归档、原生状态、真实工具执行和模型切换。多模态人类请求也保留文字与完整内容哈希；工具返回不能被提升成人类指令。持续目标的用量计数正常变化不会触发伪竞态；无输出预算的目标可使用原生压缩，有限预算在请求前拒绝不受控的原生调用且不记未发生的消费。
- 源码 CLI 14 项通过，均为本机 HTTP/SSE 和隔离配置。新增正式 CLI 原生压缩检查跨四个真实进程执行：提交、状态、压缩、重启后续聊；保留 canonical output，不请求 Chat 回退。
- 桌面 Node 逻辑 72 项通过；TypeScript／前端构建通过，构建仍有现存大于 500 KiB chunk 的体积提示。
- 隐藏 App 的真实菜单、窗口配置、手动重点、用量明细、磁盘归档、重启恢复和停止压缩均通过。模型连接在四种窗口尺寸下对齐、保存且不请求接口的检查也通过。
- Windows 原安装验证使用隔离配置与隐藏窗口，保留原 EXE 路径和二进制；最新构建与完整结果以下方补充为准。

过程记录与限制：早期专项测试曾捕获到测试 mock 在模块导入时被缓存，已改为调用时引用存储函数；竞态测试曾在每批人为追加输入，已使生产路径发现第一次变化后立即中止。旧跨领域压缩用例用虚构 90k 计数要求压缩很短的历史，在新增“必须实际缩小”的检查下被正确拒绝；已改用实际足量的来源历史，保留原证据、授权和后续执行断言。没有放宽缩小／预算／保存验证来通过旧夹具。

全部模型响应来自本地协议替身；这证明框架协议、持久化和界面链路，不能代替真实远端模型的摘要质量、数小时流程、供应商差异或真实费用验收。没有调用远端模型，也没有新建或上传 GitHub Release。私人 Taiyi Skill、真实凭据、聊天和工作区不进入暂存资源。
