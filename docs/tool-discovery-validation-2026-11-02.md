# 工具发现、恢复与外部控制管道验证

源码 `0.1.11`，2026-11-02。本次继续 [完整目标](product-roadmap.md)，修复通用工具发现链路；未新增模型提示词、供应商 SDK 或调度状态机。

## 实际复现与修改

实际安装的 Pi `1.4.0` 和 Claude Code `2.1.267` 均复现：`tool_search_tool` 报告激活 `task_list_tool` 后，下一轮仍使用旧目录，实际调用返回 `Tool not found`。Pi 更晚一轮才看到新目录，Claude 的该次运行一直没有更新。仅收到最终文本或 `completed` 不能证明所需工具成功执行，因此验收检查真实原生回执及错误状态。

受控 MCP 现在向外部 CLI 缓存当前角色允许的定义，模型转发入口仍只暴露原生已激活工具，调用仍需真实提供方调用 ID、参数及原生授权。目录通知没有确认回执，不再将它当作激活后可立即调用的保证；真正新增/移除目录项仍保留通知。过滤目录只建立一次快照，避免逐工具重复合并大目录。Claude 使用[官方工具搜索配置](https://code.claude.com/docs/en/mcp#configure-tool-search)关闭自己的重复发现层，保留原生按需发现。

`metadata.activated_tools` 保存发现状态。根会话切换会清除上一会话的动态激活；子代理及远端角色重新配置保留属于当前范围的状态。MCP 尚未注册的名称仅作为待恢复的可见性意愿，工具实际出现后重新检查名称、只读、服务器及禁止规则；不能导入代码、恢复旧授权或启动任务。旧检查点缺少该字段时沿用默认可见工具，未从模型文字猜测状态。

实际桌面运行还暴露了能力探测问题：`--help` 子进程继承了长连接控制端 stdin，在桌面进程中超时。探测现在显式使用空输入，控制 JSONL 管道保持独立。帮助参数按完整标记检查，`--session-id` 不再误算为支持 `--session`；补查实际使用的恢复及权限参数。依赖失败保留安全的校验原因或异常类型，不转抄程序 stderr 或凭据。

## 专项证据

- 实际 Pi 的 Anthropic／OpenAI 协议和实际 Claude 三条链路：第一次模型请求没有未选择工具；激活后的下一轮可调用；父进程重启后同一外部 UUID 再次调用，不重复发现；原生回执全部成功。未选择的浏览器定义也没有通过初始系统提示进入模型。
- 实际 Pi 的额外控制管道检查：保持控制 stdin 打开，等待帮助探测完成，再发送控制记录并核对原文。控制记录没有被探测进程消费。
- 原生可见性检查：会话切换、跨进程保存、晚注册 MCP、当前角色禁止、只读／隔离限制、显式角色默认工具和损坏检查点。
- 共享 MCP 检查：可发现的定义不等于可执行；未激活工具即使直接经 MCP 请求也拒绝执行。Anthropic／OpenAI 转发均只携带激活定义。
- 早期相关回归 91 项通过，232.165 秒；之后的控制 stdin 修复及清理以最终全量结果为准。

## App 与正式 CLI

隐藏 App 使用真实完整父任务创建的 Pi worker 历史，发送新提示继续该 worker；正常关闭 App 后，正式 `xuloom exec --session … --json` 再次继续。验证原始 UUID、最终结构化回执、仅一次发现和三次真实原生列表调用，未选择工具持续隐藏。

新增验收的早期失败没有计作通过：初始准备数据不完整、未隔离环境产生 502、原始 IPC 查询遗漏会话标识。最终检查先确认本机测试连接，使用完整父任务历史并传递会话标识；故意给进程设置错误的本地 API 地址环境变量后，App 仍使用已配置连接，完整链路通过。这个检查与实际发现并修复的帮助探测 stdin 超时分开记录。

模型响应均来自自有回环 HTTP/SSE，外部程序、MCP、持久化与 App／CLI 是实际生产路径。未读取私人 Taiyi Skill、个人登录或使用真实供应商额度，不能据此宣称真实模型长任务、外部 SSH 组合或原生跨平台已经验收。
