# 共享快照修复与框架清理（2026-11-04）

本轮处理两个已复现缺陷，并审查 Python 与桌面代码的未使用项、失效路径及默认请求中的重复说明。仅使用本地测试服务，没有调用真实模型供应商或外部 SSH 机器。

## 共享上下文一致性

原实现先查询最近摘要，再用另一连接读取事件最大游标。两次读取之间的发布可能既不在初始结果中，也不在后续游标之后。持久化未丢失，但自动通知漏掉。

现在初始摘要、计数与游标在同一 SQLite 读取事务中产生。确定性测试在摘要查询结束后立即用另一连接提交消息，核对该消息出现在初始快照或下一次增量中。普通查询的计数与结果也采用一致读取，写者仍可在 WAL 模式继续提交。

## 文件发布版本与分页

- 发布时复用流式、原子、完整 SHA256 校验的复制入口，生成工作目录之外的内容副本。副本和分块索引在执行端数据目录的 `scaling/shared-artifacts/`，不是新数据库或服务。
- 每块 24,000 字节，索引记录完整版本哈希及块哈希，并由清单绑定索引 SHA256。索引最多缓存 64 份；不把完整文件放进内存缓存。
- 每次读取仅寻址当前页涉及的一到两块，并核对块哈希。字节分页保留 Base64，文字为预览。篡改块即使恢复原 mtime 仍会被拒绝；索引重新加载时也验证绑定哈希。
- 工作文件修改后，原清单仍读出原版本。重新发布得到新版本和新清单，不将后来的文件内容伪装成原成果。
- 旧清单首次读取时，只从仍符合原 SHA256 的内容迁移一次；后续沿用固定版本。旧文件已经改变且未存档时明确失败。
- 继续校验运行与执行归属、目录范围、链接、32 MiB 上限、字节偏移和版本；不因缓存取消完整性约束。

隔离实测：32 MiB 文件发布约 0.179 秒，连续读 1,399 页约 7.476 秒；分页读取的文件数据合计 **33,554,432 字节**。旧算法同样页数的两次全文件扫描约为 **93,885,300,736 字节（87.44 GiB）**。前者是读取计数，后者是原算法的工作量计算，不是对物理磁盘或网络流量的测量，也不是跨机器性能结论。发布阶段另有一次性复制、哈希和索引工作。
