# 外部子代理停止与恢复验证

源码版本 `0.1.10`，2026-11-02。本次完善 Pi 的确认式停止与跨进程续聊，复用现有执行记录，不新增调度器或上下文引擎。范围仍以 [持续目标](../product-roadmap.md) 为准。

## 实际程序与故障检查

使用本机 Pi `1.4.0`、Node `24.14.0` 及已有 Claude Code `2.1.267`；这些程序没有进入发行包。模型端为自有回环 HTTP/SSE，工具通过真实 MCP 进入原生入口；未使用供应商额度、个人登录或私人 Taiyi Skill。

Pi 与历史契约 **32 项通过，60.842 秒**，其中 24 项使用实际 Pi，8 项检查持久化及对账边界。包含主动取消后同一身份续聊、已写文件后停止和父进程重启（写入仅一次）、实际 Node 崩溃、历史篡改、越界历史路径不读取、停止保存失败、原生副作用完成却没有可靠外部确认、再次取消停止握手、增量历史、Unicode JSONL、内容截断及不完整指纹拒绝恢复。

共享协议与实际 Claude 的 20 项检查通过，34.560 秒。新增停止门禁同时覆盖模型和 MCP；排队请求取得锁后再检查停止状态，避免停止前入队的工具在停止后偷偷执行。关闭本地宿主先拒绝新请求，再等待外部握手；Claude 的未知中断没有被擅自改成可恢复。

## 生产入口与 Windows 路径

隐藏桌面使用实际停止及崩溃的 Pi，检查不同恢复提示、原生 `agents.list` 回执、长模型名称省略与状态单行显示，重启 App 后再检查。检查界面不会启动模型请求。

App 退出后，通过正式 `xuloom exec --session … --json` 启动父任务并继续原 Pi worker，核对最终结构化回执、同一外部 UUID、原生文件工具记录和实际请求次数。此检查发现 Pi 的项目 ID 查找会因 Windows 长路径拼写漏查原会话；现改为显式打开已校验的历史文件，仍保留身份、文件、消息数、指纹及回执检查，不用放宽状态验证来掩盖空白重启。

验收脚本也纠正了自身的三个假设：环境变量优先级仍有效，CLI 需隔离遗留的阻断地址；正式执行结果读取 `metadata.last_run_result`，不依赖旧顶层字段；令牌计数/非流式摘要请求不能冒充模型生成请求。修正后 App 与正式 CLI 联合检查通过。

## 完成条件与边界

只有正式清空队列、abort 等待空闲、原生工具及外部完整结果内容逐项一致、JSONL 增量与旧前缀一致、文件刷盘和原生保存全部成功，才声明 `external_recovery.resumable: true`。崩溃、未知副作用、再次中断、落盘失败或篡改均保留记录并拒绝自动重放；该字段不是科学任务验收通过或 OS 沙箱证明。
