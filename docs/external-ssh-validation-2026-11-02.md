# 外部后端 SSH 与控制端恢复验证（2026-11-02）

本轮为 `0.1.17`。复用现有 `RemoteWorker`、FIFO、权限、会话锁、预算和受控 MCP；没有新增调度器、常驻服务、默认依赖或模型提示。使用实际系统 OpenSSH、开发环境的加密回环 SSH 服务和已安装 CLI，模型端点均为自建 HTTP/SSE，不使用个人登录或真实供应商额度。

## 发现并修复的问题

`0.1.16` 中，控制端重新创建并加载会话后，远端跟进可以完成，但本机 `SessionManager` 尚未加载原子代理回执的版本。保存新回执时，旧状态覆盖保护将其拒绝，最后显示 `persistence_error`。源码与原程序中的两个独立控制进程均复现了问题；它没有假报成功，但正常恢复被打断。

现在连接远端前，先在父会话现有独占写入锁下加载并核验本机回执、父子身份和远端会话 ID。句柄绑定后，后续连接与保存继续核对版本，不重新读取最新文件来掩盖冲突。远端仍负责验证自己的原生历史；控制端不复制或重建另一套执行状态。

缺失的旧回执、其他会话的记录、被替换的远端 ID、无法解析或读取的文件均保留原样并拒绝继续；已有句柄发现本机回执被改动时，在新的 SSH／模型请求前停止。全新、从未执行的排队任务仍可创建自己的首份回执。

## 实程序组合

| 后端 | 本轮安装版本 | 模型协议 |
|---|---|---|
| Claude Code | `2.1.267` | Anthropic Messages |
| Pi | `1.4.0` | OpenAI Chat Completions |
| Codex | `0.156.1` | OpenAI Responses |
| DSH／headless | `0.2.1-rc.5` | OpenAI Chat Completions |

版本来自实际安装包元数据，入口和运行时继续受既有哈希／协议检查约束。它们只存在于开发环境，不进入默认程序包；其他版本和其他供应商连接不由此自动获得兼容保证。

`tests/test_external_ssh_workers.py` 为每个后端检查以下八项：

1. 真实远端工具读取执行主机文件，与控制端同名文件区分；正常跟进保留原生 ID、原生历史与回执。
2. 缺少执行主机程序时，不请求模型、不回退本机，原生容量释放。
3. 新建控制引擎、重新加载主会话后，沿用冻结角色和同一外部会话；修改本机角色文件不会重定向旧任务。
4. 主会话取消正在请求模型的子任务，清理所属资源，不自动重发请求。
5. Full Access 下仍受父会话显式拒绝，受控 MCP 不写入被拒绝的远端文件。
6. 已绑定的本机回执被改动时，保留字节并在新连接／模型请求前拒绝旧快照。
7. 远端文件已经写入、最终模型响应仍被受控阻塞时中断 SSH；查询不重放写入、不提前报告完成，文件修改时间保持不变，预算预留释放。
8. 两个分别启动的成品 Python 控制进程执行创建与恢复，执行端也使用成品 Python；通过正式 `QueryEngine.agents` 接口，全部 Xuloom 导入来自安装包。

原生 SSH 另检查控制端重载、外来回执、缺失回执及远端身份被替换。测试使用自己的临时目录和密钥；长路径清理先核对所属目录，不按进程名清理用户程序。

- 修正辅助脚本后，旧原程序真正复现了控制端重载后的 `persistence_error`；日志与本轮修复后的检查分开保存。
