# v0.1.33 整理范围与证据

本轮把已验证的 Ultra/过程展示修复固定为基线 `19b07fa`，再做加载、程序接入与发布整理。目标是个人开发者基座；没有新增 Router、监督 Agent、企业账户服务或调度状态机。真实模型长任务、跨平台成品、物理跨机和强隔离继续按独立范围验收。

| 项目 | 实际改动或验证 | 状态/调用开销 |
| --- | --- | --- |
| 启动 | 帮助解析前不加载引擎；SDK 仅由所用连接导入；未配置模型不构造客户端；MCP/PDF/浏览器 SDK 实际使用时加载 | 不拆依赖包，不增加安装步骤、状态或模型调用 |
| 取消 | 复现事件消费者关闭后缺少取消回执，补用现有 `finish_run` 保存取消与原任务；检查点和未知工具回执继续复用 | 沿用 `last_run_result`，不新增运行状态 |
| 错误 | 现有 reason 投影为处理提示；API 错误按状态给出方向，省略服务返回的敏感正文；桌面提供设置/活动入口 | 不改变回执状态机；CLI 失败结果增加可选 `help`，不自动重试未知操作 |
| 扩展 | 增加工具注册和同步监听器两个薄入口；仓库外独立进程验证端点、工具、事件、取消、重启 | 无新插件运行时；监听异常不改写结果；模型适配限已支持的协议 |
| 后台交互 | 检查 worker 生命周期消息/取消、会话切换与另一会话问答不重复启动 worker | 普通忙碌主回合即时插话仍未提供，已列入能力边界 |
| 分发 | 真实资源更新器在临时安装目录验证：正常更新、校验拒绝、中途失败回退、删除便携目录后数据保留 | 版本/源码哈希/验证范围作为构建产物保存；无新增用户数据数据库 |
| 清理 | 静态检查结合动态入口/注册/兼容路径；移除错误的固定剩余预算展示及失真的注释，保留有用途的兼容入口 | 没有凭“未搜到引用”删除功能；默认模型输入未增加说明 |
| 文档 | 当前能力表、公开扩展说明、发布步骤与历史验证导航分开 | 历史测试数字不作为当前保证 |

## 性能基线

运行 `scripts/benchmark_base.py --ref 19b07fa --samples 3` 与当前源码，使用同一 Python 3.12 / Windows、独立配置和新进程。以下为本机三次中位数，不是所有机器的性能承诺。CLI 可输入测量拦截实际非 TTY 初始化后的输入调用，不等于真实终端屏幕绘制耗时。

| 指标 | 基线 | 本轮 |
| --- | ---: | ---: |
| `--help` | 4.11 s | 0.53 s |
| CLI 到输入点 | 5.15 s | 1.14 s |
| 创建 5 个未配置模型的空闲引擎 | 0.215 s | 0.036 s |
| 加载 1000 条、约 4.27 MB 历史 | 0.178 s | 0.143 s |
| 工具 schema 读取 100 次 | 0.233 s | 0.187 s |
| 会话 ID 列表读取 100 次 | 0.012 s | 0.009 s |
| 1000 个虚拟工具中发现工具 20 次 | 0.634 s | 0.503 s |
| 1000 条虚拟 Worker 记录的列表查询 100 次 | 0.390 s | 0.375 s |
| 已导入核心后，配置连接到首次本地模型请求 | 0.993 s | 1.051 s |

首次使用供应商仍承担 SDK 初始化；表中保留了这个成本，没有把帮助加速当作所有步骤都加速。5 个空闲引擎的首个样本进程 working set 约 145 MB → 58 MB；这是含共享/原生库的本机进程指标，不是独立引擎增量，也不能直接当作泄漏证明。虚拟工具和 Worker 测的是发现/查询开销，不代表同时执行 1000 个任务的能力。

同口径普通问答模型输入为 **6566 字符 → 6566 字符**，回环模型调用均为 **1 次**。这个口径包括测试问题及序列化工具/消息，与旧报告的 system-only 或紧凑 JSON 数字不能相减。用户历史、Skill、MCP 和配置会改变实际输入。

脚本还记录关闭后的 working set、短时重复打开/关闭的内存样本。本轮补充了 60 秒重复打开/关闭测试，216 个内存采样首尾约 71.21 MB / 72.34 MB；这是一次短时本地基线，不能证明数小时真实模型任务没有泄漏或停滞。原始数据保存在 `desktop/build/maintenance-performance-before.json`、`maintenance-performance-after.json` 与 `maintenance-soak.json`，不随源码提交用户机器的测量产物。

## 当前验证如何读取

最终候选提交固定后，运行本地全量和桌面检查，生成与提交/源码哈希绑定的 JSON 验证文件；构建记录随应用展示。构建号在构建时产生，避免在源码中反复修改构建号形成循环。跳过项、首次失败、修复后的局部复测和成品验收分别记录，不能把局部复测当作最终提交的一次全量无失败。

全量命令和发布约束见 [发布与验证](release-process.md)。本轮不调用真实供应商模型，不增加默认模型调用；真实任务成功率、成本和长时间行为仍需单独测量。
