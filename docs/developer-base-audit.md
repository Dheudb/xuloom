# 开发者基座严格检查

定位：可供开发者与爱好者复用、增量设计的通用 Agent 基座。核心提供可信执行，领域应用提供方法与验收。不以盈利、功能数量或子代理数量作为质量标准。

本目标持续推进；这份清单不构成全框架已成熟的声明。每一项需要生产入口与故障场景的证据，不能仅由存在代码或测试数量推断通过。

| 验收面 | 必须证明什么 | 当前证据与后续检查 |
|---|---|---|
| 程序接入 | 独立调用、流式事件、回执身份、取消和关闭一致；调用方不必修改核心 | `framework.md`、程序协调/退出测试；继续检查自定义工具接入与最小应用示例 |
| 扩展边界 | Skill、Subagent、MCP 的发现不授予权限；输入错误不触发副作用 | 权限与工具恢复回归；2026-11-01 新增 MCP Schema 本地预检及实际模型纠错循环测试 |
| 执行可信性 | 失败不冒充成功，结果保存先于完成通知，不静默丢弃长输出 | 执行回执、保存失败、完整输出与媒体存档测试；持续检查非内置扩展路径 |
| 会话一致性 | 单写者、旧版本覆盖拒绝、崩溃恢复不自动重复副作用 | 会话占用、事务移动/删除、进程崩溃与恢复测试；不能据此承诺任意外部系统 exactly-once |
| 权限与安全 | 显式拒绝/询问不被默认规则覆盖；明确审批与系统隔离的边界 | 权限/Plan/Windows 隔离回归；仍需检查动态扩展及能力变更路径 |
| 协作与长任务 | 队列、失败、取消、重启和父任务收尾正确，记录可靠 | 本地生命周期与子任务故障测试；真实模型长任务暂未授权，不把替身测试当作真实模型能力证据 |
| 产品可用性 | 新用户能安装、配置、执行、检查产物、恢复历史；报错可操作 | Windows 成品端到端测试与发行包审计；继续做新配置/空环境验证 |
| 可维护性 | 公开边界清楚、修改不扩散，文档与实现相符 | 逐步按现有职责提取逻辑；不新增重复调度状态或堆叠提示词 |
| 可移植性 | 源码/依赖/路径兼容有证据，平台限制如实说明 | 当前 Windows x64 成品验证；macOS/Linux 成品与各平台系统隔离仍是独立缺口 |

## 2026-11-01：MCP 参数预检缺口

复现：工具 Schema 声明整数 `count` 最大 10，原 `MCPToolWrapper` 收到 15 仍调用服务。框架只对带 Pydantic `input_schema` 的内置工具预检，MCP 发布的 JSON Schema 没有在本地执行。

修复沿用现有授权与工具纠错流程：通用 `validate_input` 不再依赖 Pydantic 类；MCP Wrapper 使用 MCP SDK 已依赖的 `jsonschema/referencing` 校验，不新增核心运行时依赖。非法参数在审批及服务调用之前被拒绝，并标为 `invalid_tool_input`、`executed=false`。直接程序调用 Wrapper 同样不能绕过校验。

声明 Schema 创建校验器时检查合法性，未知 dialect 明确拒绝。校验器不自动访问外部 `$ref` URL；需要的引用应由服务打包为自包含定义，无法解析时明确失败。导出 Schema 使用副本，防止调用方修改后改变校验语义。错误返回字段位置和约束名称，不复制可能含凭据的参数值。

证据：`tests/test_mcp_input_contract.py` 覆盖嵌套约束、必填项、类型、额外属性、正常授权、显式拒绝、程序直调、Schema 不可变、禁止外部引用联网、非法 Schema，以及真实引擎纠错循环中远端操作仅执行一次。测试使用本地替身，不调用远端模型或真实第三方 MCP 服务。

该修复不承诺任意不可信服务 Schema 都没有计算成本风险，也不改变现有 MCP 需显式配置与授权的信任边界。

本轮验证：Python 3.12 完整回归 384 项（383 通过、1 跳过）；参数/执行/纠错定向 44 项通过。源码和原 EXE 的隐藏 MCP 端到端验证均通过，包内 Python 的 MCP 参数与执行契约 23 项通过。本地原程序构建 `20261101-014741`，私人 Skill 不参与修改或打包。当前公开 Release 仍是此前发布的 v0.1.1，本轮检查过程不自动替换公开发行资产。
