## 2026-11-01：MCP 参数预检缺口

复现：工具 Schema 声明整数 `count` 最大 10，原 `MCPToolWrapper` 收到 15 仍调用服务。框架只对带 Pydantic `input_schema` 的内置工具预检，MCP 发布的 JSON Schema 没有在本地执行。

修复沿用现有授权与工具纠错流程：通用 `validate_input` 不再依赖 Pydantic 类；MCP Wrapper 使用 MCP SDK 已依赖的 `jsonschema/referencing` 校验，不新增核心运行时依赖。非法参数在审批及服务调用之前被拒绝，并标为 `invalid_tool_input`、`executed=false`。直接程序调用 Wrapper 同样不能绕过校验。

声明 Schema 创建校验器时检查合法性，未知 dialect 明确拒绝。校验器不自动访问外部 `$ref` URL；需要的引用应由服务打包为自包含定义，无法解析时明确失败。导出 Schema 使用副本，防止调用方修改后改变校验语义。错误返回字段位置和约束名称，不复制可能含凭据的参数值。

证据：`tests/test_mcp_input_contract.py` 覆盖嵌套约束、必填项、类型、额外属性、正常授权、显式拒绝、程序直调、Schema 不可变、禁止外部引用联网、非法 Schema，以及真实引擎纠错循环中远端操作仅执行一次。测试使用本地替身，不调用远端模型或真实第三方 MCP 服务。

该修复不承诺任意不可信服务 Schema 都没有计算成本风险，也不改变现有 MCP 需显式配置与授权的信任边界。

## SSH：损坏导航的离线恢复

上节复现的全目录阻断已修复。目录快照过滤单条损坏的远端引用并显示异常数量，不覆盖原始数据；损坏的工作区显示设置保持关闭/归档状态，避免无意恢复。操作指定会话时仍严格校验，不能从损坏条目连接远端，也不能通过修改导航字段创建不可渲染的行。

设置和警告条上的直接恢复入口、`remote references` / `remote forget` 共用本机设置事务。选择器只标识条目，返回数据不含草稿、绑定对象或未知原始字段。移除需确认和内容版本；在现有工作台写锁内再次校验，先保存原条目再更新导航。备份失败或旧版本请求不移除新数据；完成后刷新列表失败会如实报告已移除，不能冒充存储失败或静默重做。
