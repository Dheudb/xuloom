# 模型连接按实例绑定

这是异构子代理接入前的运行时基础，不代表角色选择、远端执行或外部 CLI 后端已经全部完成。完整范围见 [持续目标](product-roadmap.md)。

## 程序接口

```python
import os
from xuloom.core.engine import QueryEngine

async with QueryEngine(
    model_provider="openai",
    model="your-model-id",
    api_base_url="http://127.0.0.1:8000/v1",
    api_key=os.environ["MY_MODEL_API_KEY"],
    network_mode="direct",  # 或 system，明确使用环境/系统代理
    cwd="/path/to/workspace",
) as engine:
    result = await engine.run("你的任务")
```

`api_key` 和 `network_mode` 可选。省略时在创建实例时读取当前配置/环境，随后固定给该实例。显式 `api_base_url=""` 使用该协议的官方默认地址；`None` 才读取对应协议的环境地址。Anthropic 使用 `ANTHROPIC_BASE_URL`，不再误取 `OPENAI_BASE_URL`。默认地址是 SDK 协议入口，不代表任意兼容模型由该厂商提供。

主模型与压缩客户端使用同一份实例连接参数和一个薄客户端工厂；SDK 按需导入。不新增执行引擎、运行时依赖、模型权重、管理器或调度状态机。原生子代理继承父实例的实际连接参数，不在启动时重新从可变化的全局环境猜 Key 和网络设置。私有 Key 不放进可序列化的工具说明、角色、子代理记录或会话 metadata。

明确填写的模型 ID 原样用于该协议，包括通过 OpenAI 兼容网关调用的 `claude-*` 别名；不能根据前缀把主模型、子代理或压缩模型替换成父模型/GPT。独立使用压缩器时，未指定模型只查对应协议的环境配置，不再硬编码某个厂商模型。

显式传入空 Key 不会回退使用另一份环境 Key；具体 SDK 可以直接拒绝空凭据。无鉴权本地服务仍应按界面约定填写 `not-needed`。这不是系统级凭据保险箱：宿主模式下已授权的 Shell/文件工具仍可能访问用户环境与配置，不能将“客户端不串线”宣称为对恶意代码的秘密隔离。

## 切换与恢复

`switch_model_runtime(..., api_key=..., network_mode=...)` 不再写进程环境变量。桌面和 CLI 的连接选择明确传入网络设置，已有实例和其压缩器不受另一实例热切换影响。配置工具仍可更新持久配置及给未来实例使用的 CLI 环境投影；这与修改活跃客户端是两回事。

热切换先构造新客户端和压缩器，成功后才替换当前连接和清理旧思考签名。参数或构造失败保留原有连接、历史和客户端。旧客户端及失败过程中已构造的临时客户端仍由原引擎负责关闭；调用方原有显式关闭旧客户端的行为可以保留。

有未完成或排队子代理时，公共热切换 API 与桌面/CLI 一样明确拒绝，避免排队任务被中途改派到另一连接。按角色冻结不同连接的后续实现仍需接入既有队列与恢复记录，不能仅去掉此限制。

历史的 `model_runtime` 是过去执行的描述，不是重新授权。恢复聊天时不允许 checkpoint 将当前实例的 Key 改投到旧供应商/地址；当前连接不匹配时保留当前配置并恢复聊天。相同供应商与地址内仍可恢复历史模型和相应的思考选择。空白桌面草稿没有模型运行时记录，CLI 恢复时不再误关仍在使用的客户端。

## SDK 环境与重定向

- OpenAI 客户端不继承环境里的组织/项目选择器、管理员 Key 或全局自定义鉴权头；旧 SDK 不支持 project/admin 参数时不传相应参数。空组织/项目头在发出请求前去掉，省略环境头时保留必需的 JSON 协议头。
- Anthropic 使用明确的 API Key，禁用环境 Bearer/profile 自动选凭据；SDK 的全局自定义头不被带入实例，包括隐藏的租户鉴权头。自定义头目前不是 Xuloom 连接设置的公开能力，不应依赖未声明的 SDK 环境行为。
- 模型客户端不自动跟随 HTTP 重定向，防止包括 `x-api-key` 在内的认证头被转发到另一地址。返回 3xx 时需要用户修正 API 地址；网页读取/浏览器的正常导航不受此设置影响。
- Key 和连接参数不通过临时修改 `os.environ` 来“隔离”，因此不会在并发创建、重试或压缩时互相覆盖。

实现对照了 [Anthropic SDK 0.40 的原始客户端](https://github.com/anthropics/anthropic-sdk-python/blob/v0.40.0/src/anthropic/_client.py) 的鉴权与头省略语义，以及 [OpenAI SDK 1.40 的导出与客户端边界](https://github.com/openai/openai-python/blob/v1.40.0/src/openai/__init__.py)。这不等于已在所有最低依赖组合完成运行验证；原依赖声明、不同 SDK 版本及跨平台组合仍需独立验收。

## 本地证据

`tests/test_runtime_connections.py` 使用两个协议的真实已安装 SDK，向隔离本地 HTTP/SSE 服务发送请求；检查两套连接及其压缩客户端并发、Key/地址/网络归属、环境鉴权头不混入、热切换不修改环境、原生 worker 继承、结果/历史中无凭据、旧历史不重定向凭据、HTTP 重定向不被跟随、空 Key 不回退、排队期间禁止换连接，以及两阶段构造失败后的原状态和资源清理。兼容旧 SDK 缺少 project 参数的测试是构造合同测试，不冒充最低 SDK 成品验收。

另检查显式网关模型与子代理覆盖没有按名称前缀被重写。角色指定连接 ID、对相同 URL/模型的不同账户分别绑定输入/思考能力、异构连接的排队/跟进/重启恢复，仍是后续角色绑定的必需验收，不能由这些客户端测试推出已完成。
