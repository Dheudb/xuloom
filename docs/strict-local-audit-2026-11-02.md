# 请求许可与隔离清理的第二轮严格本地审查

本轮在[上一批可靠性修复](reliability-local-validation-2026-11-02.md)上追加故障注入，保留原执行器、OS 租约、原子 JSON 与请求入口。不增加常驻服务、供应商 SDK、第二套任务状态或提示词；未调用远端模型，也未读取、恢复或打包私人 Skill。

## 已复现并修复

1. **已有客户端不能绕过后来收紧的连接限额。** 原实现让不同客户端各用自己的并发配置，降低每分钟速率也沿用原启动间隔。现在排队者刷新全局配置，真正放行前再次核对；在途请求不被打断，多个参与者按较严格的限制放行，速率按上次实际启动时间计算。覆盖同进程、新旧 SDK 客户端和不同进程。
2. **损坏的嵌套许可记录不被修改。** 原实现只检查顶层列表，缺少时间字段的记录可在注册请求后失败。现在先验证队列/在途身份、所属会话、轮转顺序、策略及有限非负时间；拒绝后保留原文件。系统时钟回拨也不会无限推迟死租约回收。
3. **缺失 SID 不能被当作清理成功。** 恢复从自有 profile 名派生真实 SID，并核对记录中的 SID；没有存下 SID 的早期失败也走实际权限撤销路径。
4. **临时目录前缀不能作为删除依据。** 原实现只看目录位置和名称，不能证明属于本次启动。新启动保存文件身份；重试拒绝被替换的目录、链接和工作目录重叠。旧记录须在真实 ACL 中确认该 SID 的显式可写授权，先保存文件身份，再撤销权限；无法证明就保留目录和错误记录。只读授权不构成此证明。
5. **损坏清理记录不拖垮整个设置页。** 逐项诊断并保留原文件；没有可靠删除目标时禁止盲目重试，其他有效记录仍可查看和恢复。清理重试不重跑用户任务。

复现日志保存在忽略目录 `desktop/build/flow-policy-audit-before.log`、`flow-state-audit-before.log` 和 `cleanup-ownership-audit-before.log`。这些是自有临时目录和配置的故障测试，未删除用户目录。早期 HTTP 测试夹具混用 httpx 与 httpx2 的响应类型，已改为使用实际 SDK 的库；修复后重新运行相关测试，不将夹具失败隐藏为产品通过。
