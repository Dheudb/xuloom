# Scaling 本地验证 · 2026-11-04

本次新增独立 Scaling 工作台和 CLI，沿用现有引擎、原生历史、权限、模型客户端及外部执行器。每台 SSH 主机拥有自治主 agent，默认每组最多 50 个 worker；组长复用会话完成拆分与汇总。普通 Solo／Auto／Ultra 的递归规则与默认提示词没有因此放开。

## 已验证

- 51 个 worker 形成两个分组，组长及节点主 agent 的后续回合复用原生历史。
- 主连接断开后，节点仍完成规划、后续推理、子任务及汇总；重连取得同一任务结果，没有重复启动。
- 同一节点选择两个模型，继承的凭据不进入运行索引、事件或 SSH 命令；同一 API 的多个模型共用一份额度。
- API 配置默认从本机继承，远端直接请求供应商；亦保留远端独立配置。继承与远端独立配置均经过真实 SDK、本地 HTTP/SSE 和加密 SSH 回环。
- 接受任务后本机退出不等于取消；人类权限请求在断线期间等待答复，不自动批准。取消向节点、组长和 worker 传播，确认结束后才释放额度。
- 丢失回执、额度保存前后中断、结果保存失败、无效计划修正、缺失协调记录、显式重试和结果分页有定向覆盖。
- 1 万条队列描述和千级分组测试只验证索引／分组／内存边界，不代表同时运行了 1 万个模型。
- 隐藏 Electron 测试覆盖用量确认、SSH／节点保存、运行树、嵌套原始结果、暂停恢复及窄窗口布局。运行展示使用确定性 IPC 夹具，实际 SSH 链路另外测试。

首次取消测试用固定的 0.8 秒延迟写文件、0.15 秒后取消；繁忙机器上取消计时器可能晚于写入运行。现在改为子进程先发就绪信号、等待写入门闩，父进程取消完成后再打开门闩，检查进程能否继续写入。测试保留“取消后不得产生延迟副作用”的断言，避免仅靠延长等待掩盖问题。

另一次分片启动漏掉仓库导入路径，产生夹具导入错误；修正测试启动路径后重新运行，未将无效运行计入上表。较早的安装版控制端测试误用了源码解释器，触发了“必须导入安装包”的断言；切换实际包内 Python 后五项接入／清理测试通过。日志保留在本地忽略目录 `desktop/test-results/`。
