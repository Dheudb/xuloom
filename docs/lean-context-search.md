# 首轮输入与原生搜索

本轮减少的是默认模型请求中的重复说明和常驻工具定义，不是删除框架能力。权限决策、工具输入校验、完整结果存档、会话写者保护、子代理队列和恢复回执继续走原来的代码。

## 模型输入

- Auto 常驻五个入口：命令、文件读取、编辑、写入、工具发现。
- 搜索、Skills、计划、委派及其他专用能力通过已有工具目录加载；已加载名称随会话保存。
- Ultra 从第一次请求起直接暴露后台派发、网页搜索和网页读取入口，按通用并行收益原则使用，不增加单独的分类回合。Auto / Solo 的五个默认入口不变，详见[协作档位](capabilities.md)。
- 显式角色列表中的工具直接声明，不强制角色增加发现工具；Plan 保留退出入口。发现不授予执行权限。
- 删除重复的逐工具系统提示；保留一份简短通用规则。schema 精简展示描述和 title/examples 元数据，保留类型、引用、必填字段、枚举和约束；执行仍使用原始定义。
- 连续工具执行的可选声明采用一份共享格式说明，代码仍严格验证整张图、依赖、结果条件、参数、权限和作用域。
- 移除已失效的“自动清空旧工具结果”说明；实际长结果仍由统一存档和分页机制处理。

字符统计使用首次实际生成请求：系统文本 + `ensure_ascii=False`、紧凑 JSON 的工具定义 + 其他消息。不是 token 数，也不包含服务端隐藏提示。隔离空配置、空工作目录、无 MCP、无选中 Skill、无历史，用户输入“你好”。目录长度、日期、用户指令和已加载能力会改变数值。

## 使用原生搜索

App：**设置 → 模型连接 → 更多设置 → 联网搜索**，保存到当前连接。只选供应商接口；搜索模型与搜索 API 根地址按需填写，留空复用当前模型／连接地址，Key 始终复用该连接。没有预填供应商地址，也没有自动主机探测。不要将某供应商的 Key 配给不可信地址。

CLI 共用配置，不调用模型即可修改：

```sh
xuloom search-config --json
xuloom search-config --connection my-api --backend deepseek
xuloom search-config --backend openai --model your-search-capable-model
xuloom search-config --backend builtin
```

`--connection` 省略时操作当前连接；`--model ""`、`--base-url ""` 清除对应覆盖。CLI 与 App 保存配置均经过原有配置写入锁和凭据存储。对话中的查询仍走原有授权入口；不要直接调用底层适配函数绕过授权。

| 选项 | 调用方式 | 注意 |
| --- | --- | --- |
| 内置搜索 | 现有 DDGS | 不需要模型供应商原生搜索能力 |
| OpenAI Responses | `/responses` 的 `web_search` | 当前或指定模型必须支持原生搜索 |
| OpenAI Chat | `/chat/completions` 的 `web_search_options` | 必须使用专用搜索模型，普通 Chat 接口不自动具备搜索 |
| Anthropic | Messages 的 `web_search_20250305` | 保留搜索结果与 citations；按真实 `pause_turn` 继续，连续暂停仍未结束时返回不完整状态 |
| DeepSeek | `/v1/tools/search`、`/v1/tools/fetch` | 原生搜索查询 1–128 字符，结果 1–50 条 |
| 通义千问 | Responses 的 `web_search` | 用能返回来源的 Responses 协议；兼容 Chat 的 `enable_search` 不保证提供来源，未拿它冒充可引用搜索 |

框架在现有 `web_search_tool` 中发起独立搜索请求，再把结果交回主模型；没有改写主模型执行循环，也没有为普通问答自动附加 hosted tool。模型型搜索的 usage 计入会话，供应商返回的搜索调用用量留在工具元数据中，不估算未提供的费用。DeepSeek 的原始 Search/Fetch 本身不需要辅助聊天模型。

只发送查询，不把完整聊天历史、文件和私人 Skill 交给辅助搜索。结果包含可点击的真实来源，来源为空、协议报错或答案截断会明确失败／不完整。长结果沿用公共存档。原生搜索失败不自动回退到内置搜索或其他供应商，HTTP 重定向不会转发 Key。供应商排队与限流复用现有请求入口；更换搜索地址会使用对应地址的请求配额。

原生搜索仍受原有工作区系统隔离限制。显式连接角色的连接／模型和搜索契约固定在原有执行回执中，Key 可轮换；继承主会话的子代理同时继承其搜索设置。已冻结的旧连接回执没有搜索契约时，保持内置搜索语义。

协议依据：[OpenAI](https://developers.openai.com/api/docs/guides/tools-web-search)、[Anthropic](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)、[DeepSeek](https://api-docs.deepseek.com/guides/search/)、[通义千问](https://help.aliyun.com/zh/model-studio/web-search)。本地协议替身通过不代表远端账号已开通、第三方网关支持或真实检索质量已验收。
