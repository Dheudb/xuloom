# 本地维护

桌面入口：设置 → 备份与维护。CLI：`xuloom maintenance --help`。这些操作按需加载，不创建引擎任务、不增加 Prompt，也不调用模型。

## 备份和恢复

`xuloom maintenance backup --output D:/Backups/xuloom.zip` 保存中央会话历史、附件、工具回执、应用自建工作区和工作台布局。会校验每个文件的 SHA-256，并拒绝读取过程中发生变动的快照。请先停止任务。

备份包含聊天和用户文件，可能包含私人信息；请保存在可信位置。连接元数据和价格随备份保存，连接 Key 不导出。外部项目源码、插件代码、外部 Agent 登录、MCP 登录和系统凭据不自动迁移，请另行备份或重新配置。

`xuloom maintenance inspect backup.zip` 校验包；关闭其他 Xuloom/CLI 后执行 `xuloom maintenance restore backup.zip --confirm` 恢复。桌面支持先选择并校验，再确认正常退出后应用。它替换中央 history、workspaces、workbench.json，保留同级 `xuloom-data-rollback-*`，不会重放任务。忙碌会话的 OS 租约会阻止恢复。请等维护状态完成再重新打开应用。

跨目录恢复会重映射自建工作区的路径和历史索引。外部项目路径保留，需要在新机器重新挂载对应目录；任意用户代码中的绝对路径不被改写。复杂历史中的自定义路径仍需人工核对。

恢复后可以点击“导入恢复的连接和价格”，或运行 `xuloom maintenance import-settings`。同 ID、同协议、同地址的现有连接保留密钥；不同地址的同 ID 连接会生成新 ID，不会把旧 Key 交给新地址。原配置另存供回退；已有价格与预算优先。新连接的 Key 需要重新填写。扩展与命令型 Hook 不会因导入而自动启用。

当前限制：单个备份最多 4 GiB / 100000 个文件，不跟随链接；不包含外部项目目录的完整拷贝，也不是跨所有后端的运行中迁移。

## Windows 更新与回退

点击“查看最新版本”，从同一 GitHub Release 下载完整 Windows ZIP 和 `SHA256SUMS.txt`，放在同一目录。选择更新包后会验证校验和、内部版本及必要文件。确认“退出并应用”，程序正常关闭后才替换原安装目录，原版本保存在旁边 `.xuloom-updates` 的事务目录。下一次从原来的 Xuloom.exe 路径启动。

设置里可以选择“回退上一版本”，同样校验、暂存、正常退出后恢复。更新失败时不删除原目录；移动失败会自动回滚。若应用无法启动，可以在所有应用退出后，把事务目录中的 `previous` 移回原安装位置，保留失败目录以便排查。

这是用户主动下载和安装的更新入口，没有后台轮询或额外常驻进程。SHA-256 校验用于发现损坏，不代替数字签名；签名安装器仍是独立里程碑。不要安装来源不可信的程序包。

## 诊断导出

设置 → 导出诊断，或 `xuloom maintenance diagnose --output diagnostics.json`。导出内容只包含版本、Python/操作系统类型、会话索引数量及不可读索引计数，不包含消息、工具参数、密钥、环境变量或工作区路径。诊断包不包含完整错误日志；需要具体错误时，应另外检查并脱敏对应回执。

## 连接独立计价与扩展模型

设置 → 费用支持指定 API 连接；“所有连接”是默认价格。优先级为连接内精确模型、连接内通配符、通用精确模型、通用通配符。CLI/Python 的价格键为 `@连接ID/模型名`，旧键保持兼容。程序宿主可通过 `EngineConfig(model_connection_id="...")` 指定价格作用域。主任务和子代理仍共用任务费用累计，已发出请求的账单可能超过停止上限。

已启用插件提供的 ModelAdapter 会出现在设置 → 模型连接的 API 协议中。模型名手动填写；自动获取模型列表目前仅支持 OpenAI/Anthropic 协议。禁用插件不删除连接记录，但运行该连接前必须重新启用适配器。
