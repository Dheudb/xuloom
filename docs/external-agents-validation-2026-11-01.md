# 外部 Agent 与中央历史检查（v0.1.8）

本次范围是可选 Claude Code 后端与真实发现的中央历史缺陷，不是持续产品目标已全部完成。完整功能范围仍在 [产品目标](product-roadmap.md)。私人 Taiyi Skill 不参与读取、测试、打包或上传。

## 实现与真实过程

本机安装 Claude Code `2.1.267`，用隔离配置、临时回环认证和实际本地 Anthropic HTTP/SSE 响应检查它。既没有使用用户 CLI 登录，也没有向真实模型/媒体供应商发请求。参数依据 [官方 CLI 文档](https://code.claude.com/docs/en/cli-reference) 及实际帮助/协议行为。程序不进入 Xuloom 安装包。

先验证关闭原生工具的单次流式回执，再验证仅允许受控 MCP 的原生文件读取，随后通过生产 `engine.agents()` 创建、跟进和停止真实子代理。正常续聊仍使用同一个外部 session ID，模型请求逐次进入已有预算；没有另建队列、授权系统或任务记录。

`tests/test_external_agents.py` 共 14 项，本机开启 `XULOOM_TEST_CLAUDE_PROGRAM` 后全部通过。包括：实际 MCP/HTTP、并发写入串行约束、父框架拒绝、传输重复复用原回执、无来源调用拒绝、未知工具/模型与 Origin 拦截、检查点失败、流中断、满输出队列取消、实程序正常续聊、运行中邮件先消费再完成、逐次预算耗尽、仅取消已拥有进程和不确定恢复禁止重发。普通环境没有安装 CLI 时相关五项明确跳过，不将跳过记为验证。

## 同时修复的已复现问题

- Claude 的会话与 MCP 日志会形成超过 Windows MAX_PATH 的路径。普通 Python 清理会漏文件并报“目录不是空的”。中央历史 IO 使用长路径调用，展示及重定位仍保留普通逻辑路径；原有根目录与链接/重解析点检查保持。长路径写入、验证复制、递归枚举及原生会话删除已回归，中央历史事务 24 项通过。
- 子代理结束时 status 已是 completed，phase 却仍为 running。最终结构化回执同步更新 phase，避免 API 显示矛盾。
- 统一已有模型预算的请求生命周期，外部内部多轮也必须逐次申请；SSH 预算拒绝区分耗尽与授权不可用，不从文字猜原因。
- 外部后端配置失败或损坏恢复检查点，在派生引擎初始化阶段释放已创建的资源。
- 聊天分支不复制外部进程的会话执行权，与已有媒体请求的分支约束一致。

## 尚未验收及限制

Codex/Pi/DSH 后端、外部 SSH 组合、跨工作区移动后的外部恢复、POSIX 原生安装、供应商完整思考参数映射和真实长时间模型任务仍待推进。异常中断的外部会话当前返回结果未知，不自动重放；这不是核对式恢复已经完成。可信 CLI 的 MCP 工具授权也不是对整个第三方程序建立系统沙箱。
