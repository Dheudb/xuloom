# 状态、请求流控、隔离清理与完成依据的本地验证

本轮按确认的实施顺序交付四项修复。复用现有执行器、OS 租约、原子 JSON、会话及工具记录；不增加供应商 SDK、常驻服务、额外模型规划请求或提示词。所有模型服务均为本机确定性 HTTP/SSE 替身，未调用真实远端模型；私人 Skill 不参与实现或打包。

## 行为

- 运行树保留步骤的 `recorded_status`，另给出 `liveness`。独立只读查询缺少任务对象时保持记录中的 running/queued，并标为 unconfirmed；不会将此事实冒充中断。App 显示存活未确认，并可显式进入原授权／会话锁入口核对；没有自动重放。
- 模型 HTTP 入口按 URL/Key 的哈希身份共享请求许可。默认每个连接最多四个实际请求，Auto/Ultra 子代理数量保持原策略。会话轮转、同会话 FIFO、429 Retry-After 冷却、可选每分钟速率、流式关闭释放、取消及进程崩溃释放都在本地验证。两种 SDK 各自使用自己的兼容 HTTP 实现；主代理、子代理、压缩和外部 CLI 中继共用入口。完整用法见 [模型说明](models.md)。
- Windows 隔离在授予权限前保存所属配置、SID 与路径。清理检查返回值；失败保留记录、活动日志、界面重试及 CLI 入口，阻止新的隔离工具。重试核对真实派生 SID、工作目录和 OS 租约，不执行原任务、不接管活跃辅助进程。正常清理记录归档，避免每次状态查询扫描全部历史。限流及清理记录目录也属于隔离工具不能写入的可信区域。
- 目标完成条显示 accepted_by 的真实含义：模型报告、程序／文件检查或用户／接入程序确认。展开可读完成说明和检查；收起只改变显示，重启仍保留依据。没有给普通任务新增强制人工验收。

## 边界

这些是本地协议和故障证据，不是小时级真实模型成功率、真实限流价格、两台物理机器或 macOS/Linux 原生分发的验收。共享请求队列限于同一数据目录；不宣称跨机器的供应商账户全局配额协调。

本轮没有将系统凭据存储、MCP OAuth、签名安装器或面向用户的自动更新算作已实现。CI 仍保留此前因账号计费限制而采用的手动触发设置，没有重新启用产生失败邮件的自动运行。当前仍为通用基座的验证阶段，不能宣称无人值守生产长流程全面成熟。
