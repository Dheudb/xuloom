# 原生 SSH 子代理

v0.1.6 源码已把现有子代理队列接到 SSH 执行主机。App 与正式 CLI 的加密回环端到端检查已通过；最终全量、原安装与发布状态见[验证记录](distributed-workers-validation-2026-11-01.md)。源码通过不等于安装包已经发布。Codex、Claude Code、Pi、DSH 外部 CLI 仍按[独立后端计划](external-agents-plan.md)接入，不能把原生 SSH worker 当成它们已完成。

## 配置和使用

1. 两端安装兼容的 Xuloom v0.1.6。使用系统 OpenSSH，先在终端登录并确认主机密钥；框架不保存密码或私钥。
2. 在**设置 → SSH 远程**配置连接、远端绝对工作目录、Python 路径和平台。模型 Key、Skills、MCP 在执行主机配置。
3. 在**设置 → Subagents → 新建**选择执行位置。选择 SSH 后，连接和模型列表从该主机读取；保存定义不请求聊天模型。
4. 填写角色描述、任务指令、需要的技能和工具。所需 Skill 必须存在于执行主机，不自动复制本机私人文件。
5. 在主对话中要求使用该角色。模型通过现有 `spawn_agent` / `agent_tool`取得真实 ID，再收集结果。

主机的并发配置继续生效；超量任务进入同一原生 FIFO。Auto 与 Ultra 改变协作策略，不增加数量配额或系统权限。SSH 目标在入队前固定，模型公开连接合同在远端首次打开时固定。

同一份角色也供 CLI 使用。保存到全局 `~/.xuloom/agents/lab-review.md` 或工作区 `.xuloom/agents/lab-review.md`：

```yaml
---
name: lab-review
description: 在 lab 主机独立复核资料
executor: ssh:lab
connection: research-api
model: research-model
skills: [literature-review]
tools: [Read, Grep, Glob, Skill]
mcp_servers: []
---
只完成独立复核任务，说明证据、结论和未解决事项。
```

`executor` 省略或为 `local` 时保留本机行为；`ssh:lab` 引用已有 SSH 连接，不接受 Shell 命令。`connection` / `model` 在远端解析，省略则使用远端默认值，不继承本机 Key。`skills` 也是远端名称。`mcp_servers: []` 禁用 MCP，省略则继承主机配置。明确要求但缺失的工具、Skill、MCP 会报错，不静默降级。

交互 CLI 直接输入任务；正式 CLI 使用同一角色及执行循环：

```shell
xuloom exec "使用 lab-review 复核指定资料，再汇总结果" --cwd /path/to/work --collaboration auto --permission full --json
```

`full` 是用户选择的审批方式，仍受显式拒绝、询问和 Plan 限制。非交互执行不能模拟用户批准或回答，沿用明确的阻塞回执。查看/编写定义本身无需模型请求。

## 执行和恢复约定

- 复用 `SubagentTasks` 的任务、FIFO、父子关联和通知；后端仅持有当前 SSH 句柄，没有另建调度器、常驻服务或模型循环。
- 本机先保存冻结派发，远端先保存独立中央历史、所有权摘要及执行意图，随后才允许模型请求。相同 run ID 与输入不重复执行；角色、输入、目标或已绑定模型地址改变时拒绝。受控检查点损坏或缺失不重建成空任务。
- 每次远端工具调用先检查主机权限，再检查父会话当前的限制性祖先、别名、Plan 和拒绝保护。Full Access、只读允许不能跳过父权限；丢失控制端不能变成许可。
- 每次模型请求沿用父任务输出预留/结算，先保存父检查点再发送授权。默认不设协作总输出上限；显式限额继续生效，未知用量保守计入预留量。这不是供应商费用账单保证。
- `send` 先保存本机邮箱，再保存远端邮箱，远端真正消费并保存转录后才清除本机待投递项。消息 ID 去重，收到不等于消费；空闲代理的消息会保留到显式 `followup`，发送回执说明是否需要继续。`followup` 使用同一远端历史和冻结角色，不重放原始请求。
- 断线报告未知或中断，不自动重发模型。`result` 可检查原记录；可靠保存的成功结果不因主机离线被抹去。`resume_queue` 只恢复从未启动的排队任务。
- 跨频道取消投递到中央产物目录的控制邮箱，核对所有权与 run ID；真正拥有者清理资源并保存确认后才报告停止。锁、旧 PID 和“请求已发送”不冒充完成，不按进程名杀程序。
- 没有后台命令的已完成 worker 释放 SSH 连接，跟进时重开原历史；有后台命令时保留拥有者句柄。父会话停止/退出清理自己拥有的资源。旧后台 Shell 工具也按 agent 归属，子代理不能用任务 ID 操作兄弟任务。

系统隔离后端不支持 SSH 时在派发前拒绝，不退回宿主。SSH 使用远端账户的实际权限，不自动构成操作系统安全沙箱。

## 历史、文件与隐私

远端保留完整原生 JSON 转录及工具/文件记录，本机保存完整最终结果、回执和可解析的远端引用，不伪造本机文件路径。代理卡片的“查看远端历史与文件”打开真实会话。受控历史可浏览、复制、创建独立分支；输入、文件撤销等写入入口不能绕过主会话。继续子任务使用主会话的 `followup`。

文件不会自动同步或合并；多个角色共用目录不意味着文件编辑隔离。独立开发可给 SSH 连接配置独立目录或预先建立的 Git worktree。

配置凭据和 Skill 文件不自动传输。显式 `inherit_context=true` 会把聊天内容作为参考发送到执行主机，用户放在聊天中的资料也在其中。私人 Skill 不进入 Git、EXE 或 Release。
