# 原生 SSH 子代理接入：实施记录

2026-11-01，施工中。**当前不是完整远端 worker 已可用的声明，不替代持续目标中的分布式验收。** v0.1.5 仍是最近公开版本；本轮框架改动尚未进入原 EXE 或新 Release。

## 已有的实现基础

- `security/permissions.py` 增加可选的强制委派授权入口；正常本地调用保持原逻辑。启用后，Full Access、只读和显式允许都不能跳过该入口；异常、错误回执和控制端丢失拒绝执行，取消可传播。
- `security/delegation.py` 在父进程实时检查父任务及其限制性祖先，包含拒绝、询问、Plan、工具别名和拒绝升级。父任务允许记忆不直接授权远端；子任务的一次许可/记忆与父任务审批版本关联，不上传本机权限文件或 Key。
- `agents/role_runtime.py` 提取原生角色装配，供本地和未来执行主机共用，没有增加默认提示词。按原规则过滤工具、网络/MCP 和只读职责；显式空工具集不能得到主机默认工具，团队工具不能绕过角色拒绝。恢复使用冻结指令，不重新读已删除或更改的 Skill。
- `remote/worker_protocol.py` 定义稳定的控制身份与冻结角色。相同派发映射到同一远端会话；主机只保存所有权摘要，不保存控制 token。角色载荷拒绝凭据、Shell 程序和本机执行参数；引用上下文需要显式选择。
- 中央历史可标记必须由原控制端恢复的委派执行。普通 CLI 恢复后不能直接请求模型，绕过执行循环直接调用工具也被拒绝；切换回普通聊天清除旧的委派绑定。聊天分支已有的元数据白名单不复制控制身份。
- `DesktopBridge` 提供受控的引擎构造、角色装配和 MCP 连接钩子，供原生远端执行主机复用；不复制模型执行循环、流解析或独立管理器。
- `remote/worker_bridge.py` 已实现专用 `worker.open/start/status` 和当前频道停止端点，通过 `SSHClient(..., worker=True)` 使用同一系统 OpenSSH 传输。稳定身份和运行意图先落盘；打开、启动幂等；变更输入、角色、模型绑定、损坏控制或缺少必要工具/MCP 均不会改为另一种执行。远端自己的 Key 留在执行主机。
- 每次真实远端工具操作等待当前控制端的 `worker_permission` 决定；独立 Full Access、只读允许和角色配置不能绕过它。普通 CLI 恢复受控 worker 会被拒绝。第二频道只能如实报告写者占用，不能把自己未执行的停止称为已确认；原拥有者停止后保存取消状态。同目录下其他会话不会通过刷新事件泄露给 worker 控制端。
- 委派任务停止启动全局记忆提取任务；保留原有自身上下文压缩和结果历史。静态调用核对后删除未暴露于工具 schema、没有调用者的旧协调模式私有方法及多余导入；没有移除现行原生批量启动、队列、协调者父任务或公开模块接口。

以上仍不是已完成原生 SSH 队列派发、UI 或外部 CLI 的证据。端点及故障检查见 [当前验收记录](distributed-workers-validation-2026-11-01.md)。原生控制端尚需把实际权限事件、远端结果与既有 registry/任务句柄接通；不要把“有一个 RPC 进程”当成整个分布式功能已交付。

## 下一步按同一原生生命周期接通

1. **专用 SSH worker RPC 端点（已补基础执行）。** 复用系统 OpenSSH、现有 JSONL 和 DesktopBridge。普通 SSH 聊天入口不变；已开放绑定当前 worker 的打开、启动、状态、授权答复和当前频道停止，不暴露任意项目/会话改派。新的 run ID 可续用已拥有的同一引擎/历史；消息邮箱和跨频道停止尚待下述原生控制端接通，不视为完整生命周期已完成。先验证主机身份和协议，再恢复历史；老版本没有能力时明确报错。
2. **先保存真实身份，再执行。** 本地原生 registry 在进入队列前保存冻结角色、目标与私有控制身份；远端通过稳定身份创建独立中央会话。重复打开幂等，任务启动的 run ID 与输入摘要也幂等；运行意图持久化后才允许第一次模型请求。失去回复不重放。
3. **模型和资料在执行主机解析。** `connection`/`model` 引用远端自己的已配置连接，冻结公开连接合同，Key 不回传。所需 Skills、MCP、工具缺失清楚报错，不能用本机路径或本机 Key 兜底。父任务处于系统隔离且不支持 SSH 时，派发前拒绝，不退回宿主。
4. **每次工具操作经过父权限。** 远端先做自己的实际授权和准备，随后通过当前绑定的频道把真实工具请求发给父任务；父进程用实时规则处理，必要时使用现有审批 UI/非交互拒绝机制。不让模型转抄权限决定。远端明确要求询问的场景在父任务 Full Access 下也必须询问。
5. **父子关联与运行根分开。** 每个远端 worker 是自己主机上的会话执行根，原生父记录保留逻辑父子关系、实际机器/目录、远端会话 ID 与真实结果回执。长对话 JSON 留在远端中央历史，本机原生子代理记录保留可解析的远端引用和完整最终结果；不伪造本机文件路径。UI 可导航到真实远端会话查看历史和文件。
6. **沿用原生队列和控制所有权。** 本地 `SubagentTasks` 继续负责容量、排队、任务与通知；可增加当前后端的连接/控制句柄，不增加第二套调度状态机。跟进、消息与停止只操作该记录拥有的频道/会话。后台命令仍归其执行主机的现有管理器所有；父任务退出要关闭自己持有的远端执行资源。
7. **连接、执行与保存分开报告。** 活跃频道可证明当前运行；重连后的锁占用只能表示会话有写者，不能直接冒充原模型仍在工作。已保存的完成回执、停止确认、暂存/中断和结果未知分别展示。收到停止请求不等于停止完成；不能用历史 PID 或进程名杀远端进程。若需要跨频道停止，使用带所有权及 run ID 校验的现有中央产物控制邮箱机制，并等待实际拥有者保存确认。
8. **同步 App 和 CLI。** 角色设置增加真实执行位置和远端模型连接入口；角色文件被桌面与 CLI 共用。先做独立回环 SSH、多账号本地模型协议、审批、失败/断线/保存故障、并行/排队/跟进/取消/重启、产物导航的生产入口验证，再发行。两机、POSIX 和真实模型验证另列；不使用私人 Taiyi 或收费接口。

Codex/Claude/Pi/DSH 外部 CLI 仍按 [外部后端计划](external-agents-plan.md) 独立接入原生生命周期，不能以此处的身份协议代替其实际流、审批和恢复协议。完整范围见 [持续目标](product-roadmap.md)。
