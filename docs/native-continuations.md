# 原生条件续跑

Xuloom 在既有 `QueryEngine` 的下一次主模型请求之前检查已声明动作。主模型先确定工具、完整字面参数、依赖和回执条件；条件成立时，执行循环直接调用原生工具执行器。需要理解新证据、出现错误或执行范围变化时，回到主模型。

App、交互 CLI、非交互 CLI 及使用该引擎的原生子代理共用此路径。用户无需先搜索或要求调用 `tool_sequence`。正常问答不产生动作图；模型未声明计划时保持原有工具循环。外部 Codex／Claude／Pi／DSH 的独立模型循环不会被 Xuloom 偷偷改写。

## 声明协议

正常工具参数可附带可选 `__xuloom_continuation` 对象。执行器剥离它后才执行原工具；Hook、权限、系统隔离与供应商工具不会收到这份元数据。现有原生工具参数模型无需修改。

例如用户明确要求写入并读取核对一个已知文件，`file_write_tool` 可以发出：

```json
{
  "file_path": "/authorized/workspace/notes.md",
  "content": "Already determined contents",
  "__xuloom_continuation": {
    "nodes": [
      {
        "id": "read_back",
        "tool": "file_read_tool",
        "arguments": {"file_path": "/authorized/workspace/notes.md"},
        "depends_on": ["root"],
        "when": [{"step": "root", "path": ["ok"], "equals": true}]
      }
    ]
  }
}
```

`root` 指携带声明的当前工具调用。每个节点包含唯一 `id`、当前可用的 `tool` 和完整 `arguments`。`depends_on` 默认 `["root"]`，其他依赖须为声明中较早的节点；`when` 默认空数组，各项必须引用依赖祖先的完整结构化回执并全部成立。不得使用占位符、猜测路径、动态代码表达式或语义条件如“论文结论正确”。如果后续参数需要阅读新内容后决定，省略声明或使用 `nodes: []`。

协议说明只在共享工具说明中出现一次，每个工具仅增加紧凑的可选字段，不重复大份图 Schema。Schema、计划生成及最终回答的 token 全部计入实际模型 usage；不能只计算省掉的往返而忽略协议开销。

## 执行规则

- 根动作执行前检查完整声明、工具可见性、参数、依赖和条件引用。一次最多 128 个节点；当前每个引擎保留一份活动计划，不覆盖尚未结束的计划。
- 每个后续动作仍经过现有授权入口，独立进行参数检查、Hook、Plan／角色限制、审批、系统隔离和保存；声明计划不是提前授权。
- 条件明确为假时跳过该分支及其依赖节点；条件字段缺失、结果截断或需要新解释时交回模型。
- 唯一可执行动作直接执行。多个依赖已满足、可安全并发的只读动作使用既有并发上限并行，汇合节点等待全部依赖完成；其他多候选情况交回主模型，不新增选择器模型或按声明顺序猜测执行。
- 命令未结束、非零退出、失败回执、新输入、暂停、取消、工具替换或执行范围改变均停止自动推进。审批返回后再次核对绑定。
- 原模型响应及每个合成工具调用／回执沿用原会话历史格式。App 显示实际子工具与续跑／回退说明，CLI JSON 事件包含相应 `loop_transition`。

对于声明过大或无法作为完整 JSON 保存的观测，安全退回原模型路径；原生长输出归档与返回不因此被截掉。当前完整观测快照上限为 64 KiB，声明上限为 256 KiB，这是续跑缓存边界，不是任务输出预算。

## 保存和恢复

动作图、节点状态和完整观测快照存入既有中央会话元数据 `native_continuation`；没有额外任务数据库或队列。图状态与实际工具回执在同一个会话检查点保存。原单写者锁、修订校验及执行前意图记录继续生效。

重新加载时核对原始声明、图摘要、原生回执、观测摘要、模型连接和执行范围。已保存完成的动作不会重放；“已执行但尚未写入聊天消息”的回执可从原记录补回。处于执行中、证据缺失、工具不再可用或绑定变化时，停止自动恢复并交回模型核对。加载历史本身不执行动作；用户继续任务或原调度入口恢复后才进入执行循环。

“动作图耗尽”不表示整个任务已完成，不替代原子代理等待、持续目标或领域验收。

## 请求替代记录与范围

原生请求边界记录 `continuation_substitution`，绑定边界 ID、图／根动作摘要、节点、前置回执、实际工具及结果摘要，标明该路径没有发出主模型请求、没有调用选择器。记录保存在现有元数据及执行事件中；它证明该边界通过工具推进，不能预测未发生请求的 token 数，也不证明整个任务必然更省。

原 `tool_sequence` 保留为显式调用接口，复用同一原生授权执行器。新机制无需模型先发现它。

参考 [HarnessMM 论文第 4 节](https://arxiv.org/html/2610.32813v1#S4)及[原生接入说明](https://github.com/YuhuaJiang2002/HarnessMM/blob/c8f19947e59feaa8103c05155bd79ef3eb084730/docs/INTEGRATION.md)。本轮实现原生图声明、条件复用、请求边界接管及替代证据，没有导入研究运行器、Node 依赖、固定供应商选择器或离线 RSI 训练。真实模型的主动声明率、任务质量和完整费用仍需单独对照验收，不能使用论文收益作为 Xuloom 实测。
