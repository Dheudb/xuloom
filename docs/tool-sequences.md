# 条件式工具续跑

这是显式工具接口。普通工具调用携带动作图并由下一次模型请求边界自动推进的机制，见[原生条件续跑](native-continuations.md)，无需先发现 `tool_sequence`。

`tool_sequence` 把已经确定的工具动作与可检查条件放在一次原生工具调用里。满足条件时调用现有执行器，未知信息、条件不明或失败时将结果和剩余步骤交回主模型。它处理工具动作；子代理 Pipeline 继续处理独立任务，没有增加另一套调度或存储系统。

App 和 CLI 共用。通过已有 `tool_search_tool` 搜索“工具序列”“续跑”或 `literal tool sequence` 并激活 `tool_sequence`。无需新增模型、供应商、账号或协作档位，普通问答不加载这份 Schema；未添加全局长提示词或优化器模型。

## 使用条件

后续工具和字面参数必须已经确定。例如用户明确要求构建和测试，且命令和目录已知，构建成功后才运行指定测试。未知文件内容、新证据的解释或依赖未见输出的参数仍交给模型。工具不会替换占位符、拼接命令或推断科学结论，也不会因文件被修改就自动增加测试动作。

工具参数示例：

```json
{
  "steps": [
    {"id": "build", "tool": "command_tool", "arguments": {"argv": ["npm", "run", "build"], "wait_ms": 10000}},
    {
      "id": "test", "tool": "command_tool", "arguments": {"argv": ["npm", "test"], "wait_ms": 10000},
      "when": [
        {"step": "build", "path": ["status"], "equals": "completed"},
        {"step": "build", "path": ["exit_code"], "equals": 0}
      ]
    }
  ]
}
```

这里只对较早步骤的完整结构化结果做严格相等比较，所有 `when` 条件须成立。布尔 `true` 不等于数字 `1`；缺字段、重复 JSON 键、截断内容或不完整分页文本不能成为成立证据。命令仍在运行或失败时交回模型，模型可用返回的真实 `command_id` 继续查询。

## 执行与恢复

- 第一步前校验整个列表、工具可见性及参数；第一版最多 128 步，不支持递归序列。所有工具须已在当前会话可用。
- 每个动作仍经过 `_execute_tool_wrapper`：参数校验、独立权限询问、角色/Plan 限制、系统隔离、执行检查点和结果持久化。编排器不授予写入权限，也不额外要求批准整个序列。
- 步骤边界和审批返回后检查执行范围及上级收件箱。新消息、工作目录、模型连接、模式或隔离范围变化会停止旧的待执行动作；新输入由既有会话机制交给模型，编排器不把它标为已读。
- 工具实例或接口定义在执行中被替换时停止旧计划；审批返回后也再次核对，避免把旧参数交给新的执行器。
- BeforeToolUse Hook 修改已声明参数时先交回模型，不能执行修改后的动作。原受控工作区路径路由仍保留。
- 取消、跨进程目标暂停和结果保存失败会停止续跑。使用外层调用 ID 与步骤 ID 派生稳定子调用 ID，复用原日志，不自动重放不确定操作；缓存显示文本不会冒充新的结构化观测。

App 显示编排图标和每个实际子工具，重开历史不执行动作。完整输出沿用长结果归档；`tool_sequence_step` 记录原调用、步骤、动作与回执摘要哈希。尝试、成功返回和剩余步骤分开计数，没有增加原始凭据副本。

“序列完成”仅表示已声明动作的执行结束，任务验收、子代理等待和持续目标完成依据继续使用原协议。完整供应商调用 usage 保留，不预报节省百分比；少一次主模型回合并不保证完整任务一定更便宜。
