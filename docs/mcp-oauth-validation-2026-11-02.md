# MCP OAuth 本地验收

日期：2026-11-02。沿用现有 MCP SDK、OS 租约、配置编辑和原子保存；没有增加模型规划请求、提示词、供应商 SDK 或常驻服务。范围为 HTTP MCP 的动态注册 / 客户端元数据文档登录、刷新、退出及 App/CLI 共用。固定预注册客户端入口和真实提供商验收不包含在已完成声明中。

## 可核验的约束

- 只在用户明确点击或运行登录命令时进行交互注册与授权。普通连接没有凭据时，在网络前返回需要登录；403 授权不足也不会自动打开浏览器。
- SDK 提供 PKCE、发现和交换流程，外层恢复加密的授权服务器/资源元数据及真实过期时间。重启后的刷新不猜测 `/token`，不将资源服务器当成授权服务器。
- 回调监听仅绑定随机端口的 `127.0.0.1`，检查 Host、随机路径、state、issuer、重复参数、长度与超时。错 state / issuer 不消费正确回调；手动粘贴也经过相同校验。
- 成功的 MCP SSE 只等响应头，不等待事件流结束；授权元数据和令牌响应另有大小及读取期限。HTTPX 中间鉴权响应保留有界缓存，避免重复读取已消费流。
- 刷新使用跨进程 OS 租约；轮换结果先可靠保存，再重试被拒绝的 MCP 请求。未返回新 refresh token 时保留原值；空令牌、控制字符和非法过期值在保存前拒绝。
- 后台每次请求核对当前配置及回执版本；目标变化、退出、删除服务均不能恢复旧授权。取消时不在磁盘写入尚未收尾时释放写锁，避免覆盖随后完成的退出。
- SDK/HTTPX 的敏感诊断仅在当前 OAuth 上下文内脱敏，授权码和令牌不进入聊天、模型消息或进度记录。UI 授权事件绕开 turn recorder，回调由专用 RPC 接收。
- OAuth 必须有原生保护后端，不允许明文降级。磁盘保存失败不报告登录完成；旧账号保持原值。显式登录可修复不可读密文，退出可隔离损坏回执并清除本地授权。
- App 将本项目授权记录的公共文件状态纳入连接变更检查；CLI/另一进程登录后，下一次任务会重新连接。此变更检查不解密令牌。
- 系统隔离仍禁止 MCP 和宿主 OAuth；`mcp-oauth` 记录目录加入不可与可写工作区重叠的可信目录检查。

## 测试方法

`tests/test_mcp_oauth.py` 使用实际 MCP SDK、HTTPX、原生 Windows DPAPI、真实文件锁与两个不同端口的本机 HTTP 服务。服务端实际核验授权码、PKCE challenge/verifier、目标 resource 和轮换令牌，包含真实新进程 CLI 登录/刷新及真实 Streamable HTTP 初始化。不是用静态 JSON 成功回执替代执行。

`desktop/tests/mcp-oauth.e2e.cjs` 使用隐藏、独立 HOME/配置/数据目录的 Electron。没有配置聊天模型；验证图形配置、未登录提示、手动回调、密文文件、实际 MCP 连接、取消重登、退出。浏览器授权由自有回环服务完成，未打开用户浏览器。另重跑已有 MCP 市场与手工请求头连接流程。

此轮所有授权服务均为自有本机回环夹具，没有远端模型调用，也没有真实第三方账号登录。macOS/Linux 原生密钥服务、物理 SSH 两机、实际提供商差异仍需独立证据。
