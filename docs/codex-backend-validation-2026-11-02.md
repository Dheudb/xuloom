# Codex 异构后端验证（2026-11-02）

范围：`0.1.14`，用户已安装的 Codex `0.156.1`，Windows x64 / Python 3.12。使用独立临时目录和本地 HTTP/SSE/MCP 服务，没有读取个人 Codex 登录、使用私人 Skill 或调用真实供应商。安装与发布状态在末尾单独记录。

## 实现与边界

- 后端是官方 App Server JSONL，模型协议是 OpenAI Responses。现有角色、原生 FIFO、独立连接、权限、预算与中央历史继续使用；没有新增供应商 SDK、Agent 调度器或模型生成的 ID 绑定。
- 每个 worker 有独立 CODEX_HOME。子进程只取得本次回环令牌，真实供应商凭据留在 Xuloom 的已有 SDK 客户端；不使用个人模型配置、登录或项目插件。
- 工具目录只向模型暴露当前激活的原生 MCP 工具。Responses 的命名空间、工具身份、增量参数、完成项及整批调用经过校验，完整回执确认前不释放任何工具调用。内置或托管工具、未知执行事件、重复或变化的身份、负数 usage 及流截断不能变成工具执行。
- Codex 的自动批准只免去它自己的第二层询问，不覆盖 Xuloom 父任务的拒绝与审批。工具仍经同一原生授权入口。
- 正常完成必须有匹配的线程和回合、成功退出、原始协议/诊断落盘及最终检查点。恢复前核对真实 rollout 文件所属目录和 SHA256；丢失或变化时拒绝空白恢复与重放。
- 主动取消只清理本次拥有的进程；Codex 当前不声称已完成 Pi 式的中断历史对账。结果未知时 `resumable: false`，不能自动再次执行可能有副作用的任务。
- 原始外部 JSONL 已保存，完整中间历史尚未全部映射到 App。程序本身是用户信任的第三方进程；原生工具权限不等于为它建立操作系统沙箱。不支持的系统隔离组合在启动前拒绝。

## 已执行的专项检查

`tests/test_codex_responses.py` 使用实际安装的 Codex 和本地协议服务器：

1. App Server 正式初始化、命名空间工具调用、原生 MCP 读取与最终回合事件；确认第二次模型输入实际包含读取证据，不能只凭模型的最终文字认定成功。
2. 原生队列派发、同 worker 跟进、父引擎关闭后新引擎恢复；真实线程 ID 和 rollout 路径不变。
3. 缺失、被修改的 rollout 在新模型请求之前拒绝。
4. 父任务显式拒绝读文件时，证据不会出现在上游模型输入。
5. 取消后子进程被清理，未确认的执行拒绝重放。
6. 最终检查点失败、诊断文件 flush 失败不能显示 completed 或可恢复成功。
7. Responses 分片参数、非法后续调用、未知内置执行事件、身份错配、重复完成项、非法 usage、完成前 EOF，以及有效的可选 null caller。
8. 回环代理只接受本次自己的目标地址与令牌，不会成为任意目的地址转发代理。

`desktop/tests/codex-workbench.e2e.cjs` 通过隐藏 Electron 窗口运行源码版 App 和正式 CLI：主代理使用 Anthropic Messages，Codex worker 单独绑定 Responses 连接；同一线程先由原生入口创建，App 恢复和跟进，再由另一进程的 `xuloom exec --json` 继续。检查后端标记、真实模型连接、工具证据、中央历史和配置入口。图形设置直接创建 Codex 角色，不要求改源码。

旧 Claude Code / Pi 可选实程序专项另行回归：50 项通过，耗时 111.540 秒。它们也只访问本地协议服务。
